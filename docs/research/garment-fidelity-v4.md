# Сохранение вещи при стилизации — #109

Проверка 2 ноября 2026 на трёх предоставленных владельцем фотографиях:
чёрная футболка с принтами, худи с золотым принтом, полосатые брюки.
Это измерение ограниченной выборки, а не гарантия качества для любого снимка.

## Причины и изменение

Заполненный шаблон навязывал стандартный узкий корпус. `silhouette=unknown`
в ответе JEV не означал, что вещь действительно узкая. Теперь одежда
редактируется по источнику, а шаблон задаёт допустимую область размещения.
Для измеримого корпуса численное отношение ширины к длине дополняет признаки.
Подол определяется по центральной части, отдельно от манжет; плечевая линия —
по двум боковым точкам корпуса, независимо от прозрачного отверстия горловины.
Тонкий открытый ободок капюшона не считается плечами: нужна поддержка
не менее половины ширины корпуса непрозрачными пикселями.
Высота капюшона не входит в длину корпуса. Ранее измерение ошибочно называлось
«горловина–подол» в инструкции; теперь название соответствует линии плеч. При посадке остаются только равномерный масштаб и
перенос: растягивание отдельных осей или штанин не исправляет результат.

Распознанные описания кроя убраны из инструкции редактирования: они не должны
заменять наблюдаемую форму стандартной «обычной длиной». Тип и цвета сохраняются,
полные признаки по-прежнему участвуют в регистрации и подготовленной версии.
Для белых и бежевых вещей используется серый фон генерации: на белом фоне
Photoroom ошибочно делал белую ткань полупрозрачной. Подготовленный оригинал
и его alpha не меняются.

Для обычного худи с длинными рукавами после исходников добавляется цель
редактирования: расправленная поза с измеренным корпусом, без дизайна вещи.
Она применяется только при измеримом отношении 0.4–1.0. Остальные длины и рукава
не получают эту геометрию. Результат41372576603 сохранил корпус, но проверка на манекене выявила
манжеты сбоку от запястий. Прежняя геометрия ошибочно считала его подходящим.
Теперь контакт проверяется в отделённом от корпуса рукаве у каждого запястья;
край широкого корпуса не может заменить манжету. Шаблон исправлен под эти
координаты с сохранением измеренного корпуса. Повтор41372728421 снова
скопировал сложенные рукава и был отклонён; устойчивость генерации ещё не доказана.
Для остальных худи используется исходный фронтальный снимок и явное изменение
позы существующих рукавов с сохранением их фактической длины. Капюшон опущен; клиент помещает голову перед ним,
головной убор — перед головой. Крой и длина вещи не заменяются размерами тела.
Для брюк расширена допустимая область ширины при сохранении полной длины.

В каталог попадал весь холст из-за удалённых пикселей alpha=1. Миниатюра теперь
игнорирует этот уровень шума при выборе границ. Пиксели внутри границ и полный
холст примерочной сохраняются.

## Ограничения

Численная проверка работает только для устойчивого видимого корпуса верхней
одежды. Для скрученных брюк и неоднозначных исходников она не выдаёт фиктивную
оценку. Семантическая проверка JEV требует подтверждения сохранности каждой из четырёх
групп признаков с confidence ≥ 0.7. Это порог допуска наблюдаемых признаков,
а не откалиброванная вероятность визуальной точности. Уверенное изменение
(confidence ≥ 0.85) даёт `illustration_identity_changed`; остальные неподтверждённые
ответы — `illustration_identity_unconfirmed`. Прежний код ошибочно пропускал
неуверенность и слабое `preserved`. Интеграционная регрессия воспроизводит это
и проверяет недоступность результата без подтверждения, отсутствие скрытого
повтора и явный успешный повтор с достаточным подтверждением. Даже подтверждение
JEV не гарантирует точную типографику, мелкие детали или текстуру принта.

Результаты провайдеров не считаются готовыми только по HTTP 200. Один ответ
Gemini для брюк завершился `incomplete`; GET сохранённого interaction подтвердил
этот исход без нового POST. Завершённые ответы проверенных трёх вещей содержали
по одному изображению — гипотеза о выборе промежуточного кадра не подтвердилась.
Нормативный смысл `incomplete` описан в
[Gemini Interactions API](https://ai.google.dev/api/interactions-api).

Новая стадия `fidelity` требует дополнительный JEV-запрос и может увеличить время
обработки. Вырезка сохраняется до этой стадии атомарно; неизвестный исход запроса
не повторяется. Тестовые фото, промптовые прототипы и временный workflow вынесены
из релизного diff. Старые v2/v3 публикации и подготовленные исходники сохраняются.
