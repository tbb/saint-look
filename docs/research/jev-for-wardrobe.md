# Jev для типа, цветов и оценки луков

Проверено 25 октября 2026 по официальным `typesafe.ai` и `docs.typesafe.ai`. Регистрация, покупка кредитов и вызовы API не выполнялись. Качество на наших фотографиях не измерено.

## Вывод

Jev — подходящий кандидат для небольшого эксперимента с классификацией вещей, но пока не подтверждённая замена Gemini в рабочем сценарии. Его **обработка изображений прямо обозначена как не готовая к production**. Для оценки луков по уже извлечённым текстовым атрибутам Jev тоже можно исследовать: это другой эксперимент, не зависящий от готовности vision. [Изображения](https://docs.typesafe.ai/images), [Score](https://docs.typesafe.ai/primitives/score).

## Что документировано

- Актуальная версия — `jev-1.14.0`; цена $0.042 за миллион входных токенов, выход бесплатный. Английский — основной язык обучения и лучшего качества; неанглийские задачи требуют проверки. Русские названия можно получать из нашего словаря по идентификаторам, не требуя генерации русского текста. Последнее — предлагаемое решение, а не гарантия провайдера. [Models](https://docs.typesafe.ai/models).
- Изображения принимаются Jev 1.13 и 1.14 только с `TypeSafe-Danger-Zone-Images: true`. PNG/JPEG, каждая сторона 280–1568 px, до 16 MiB на файл. API не подгоняет размеры автоматически. Фото лучше указать один раз в `state`: повторение ссылки вставляет изображение повторно. Каждый image token оплачивается по обычной входной ставке; `usage.input_tokens` включает изображения. Формула оценки image tokens ещё не опубликована, поэтому точную цену за фото заранее не обещаем. [Images](https://docs.typesafe.ai/images).

## Как выразить нашу задачу

Это предлагаемый дизайн на основе документированных примитивов, а не реализованная схема:

| Задача | Примитив и обработка |
| --- | --- |
| Тип вещи | Один `Choice` из нашего перечня типов с описаниями и возможностью неопределённого результата. Ключи переводим на русский локально. |
| Несколько основных цветов | Независимый `Noul` на каждый цвет палитры: входит ли он в основные цвета самой вещи, исключая фон и мелкие детали. Порог, максимум цветов и неопределённость обрабатывает код. |
| Пригодность фотографии | Отдельные `Noul` для одной самостоятельной вещи, отсутствия человека и читаемости снимка; пара обуви считается одной вещью по нашему словарю. |
| Оценка готового лука | `Score` по описанной шкале совместимости/соответствия случаю, используя текстовые атрибуты вещей и контекст пользователя. |

`Choice` выбирает **ровно один** вариант; распределение вероятностей по цветам в одном Choice нельзя трактовать как многозначный список цветов. `Noul` возвращает вероятность ответа «да», а не долю площади цвета. `Score` задаёт место на описанной шкале. Все необходимые вопросы можно собрать в одном запросе; они не дают свободный текст или embedding-вектор. [Choice](https://docs.typesafe.ai/primitives/choice), [Noul](https://docs.typesafe.ai/primitives/noul), [Score](https://docs.typesafe.ai/primitives/score), [примитивы API](https://docs.typesafe.ai/primitives).

Типизированность и высокая confidence не доказывают правильность распознавания. На 2–3 фото проверим интеграцию, но не откалибруем пороги и не докажем качество на всём гардеробе. Для отбора кандидатов и окончательной оценки луков потребуются отдельные примеры; сходство embedding-векторов само по себе не означает, что вещи сочетаются. Это инженерные ограничения предлагаемого подхода. [О confidence](https://docs.typesafe.ai/confidence), [интерпретация Score](https://docs.typesafe.ai/primitives/score).

Практический следующий шаг после выбора — сравнить Jev на тех же публичных фото с базовым распознавателем, записать фактический `input_tokens`, ответы и неоднозначности.
