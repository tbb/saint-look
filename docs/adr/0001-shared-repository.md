# Общий репозиторий для backend и iOS-клиента

Backend и iOS-клиент разрабатываем в одном репозитории, в каталогах `backend/` и `client-ios/`: первый этап требует согласованных изменений обеих частей, и общий репозиторий позволяет менять контракт API и клиент одним коммитом. Контракт и решения храним в `docs/`; отдельные репозитории пока не дают преимуществ независимых команд или разных прав доступа. Сборка и развёртывание частей остаются независимыми; специальные инструменты управления монорепозиторием не требуются.

## CI

Минимальные проверки настраиваем вместе с реализацией: backend на Linux, iOS-клиент на macOS, отдельными заданиями в `.github/workflows/`. Изменения одной части запускают её проверки, изменения общего контракта — проверки обеих. Реальные вызовы AI запускаются отдельно по запросу, чтобы обычные проверки не расходовали пробную квоту.

24 октября 2026 пользователь решил открыть репозиторий, включая код, историю и проектные документы, чтобы использовать бесплатный CI. Для публичного репозитория стандартные GitHub-hosted runners бесплатны, включая используемые `ubuntu-latest` и `macos-26`; платные larger runners не используем. Условия описаны в [документации GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

Это заменяет первоначальное требование подтвердить приватную квоту перед первым запуском. Если репозиторий снова станет приватным, workflow блокирует все задания до ручного допуска `ACTIONS_BUDGET_VERIFIED=true`: его можно дать только после проверки включённой квоты и бюджета платного превышения $0 с остановкой использования. Публикация репозитория не меняет бюджет хостинга и внешних AI-провайдеров.

## Проверка и доставка iOS

В CI собираем iOS-приложение и запускаем тесты в iOS Simulator. Первую ручную демонстрацию сквозного сценария выполняем в симуляторе на Mac с настоящим dev-backend. Распространение сборок через TestFlight относится к следующему этапу.

## Выкладка первого этапа

Проверки запускаются автоматически на PR, выкладка backend — вручную через GitHub Actions после успешных проверок, с возможностью вернуть предыдущую версию приложения. Откат версии приложения не означает автоматический откат данных. Выбранное dev-окружение, хостинг и ограничения хранения описаны в [ADR-0002](0002-managed-dev-hosting.md).

## Раздельные проверки и время обратной связи

1 ноября 2026 пользователь подтвердил независимые проверки backend/iOS и
оптимизацию UI-тестов. `backend-ci.yml` проверяет сервер, контейнер и допуск
к выкладке; `ci.yml` проверяет iOS. Изменения `shared/` и `docs/api/` запускают
оба workflow, изменения серверных UI-фикстур — также iOS. Backend-релиз требует
успешный серверный CI точного SHA из main; TestFlight — полный iOS CI точного SHA.
После изменения только другой части полный нужный workflow можно запустить
вручную на main. Узкие ручные UI-прогоны не заменяют полный допуск TestFlight.
Старые rollback-коммиты проверяются по прежнему полному CI.

Гардероб и луки распределяются каждый на две независимые группы по измеренным
длительностям. Новые тесты автоматически входят в группы; отдельная проверка
подтверждает отсутствие потерь и повторов. Крупный текст и четыре визуальных
профиля остаются обязательными для полного iOS CI. Каждый job использует свой
backend и Simulator; параллельные тесты не делят глобальное состояние фикстур.
Повторный сценарий ради manifest smoke убран: обычные сценарии используют
тот же явный XCTest manifest. Видео остаётся у визуального светлого iPhone;
остальные прогоны сохраняют xcresult, скриншоты и времена тестов.

Зависание локального XCTest завершается ошибкой после 180 секунд без вывода,
600 секунд на обычный сценарий (900 для визуальных journeys, где успешный
сценарий крупного текста занимал 655 секунд) или 300 секунд до первого сценария.
Лимит обычного UI job — 35 минут. Автоматических повторов нет. Эти пределы
ограничивают ожидание, но не доказывают исправление сбоев Simulator (#98).
Исходные длительности групп и измерения каждого следующего прогона сохраняются;
ускорение оценивается по реальным jobs с учётом очереди macOS runners.
