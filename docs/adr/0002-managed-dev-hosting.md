# Управляемый dev-стенд на Fly.io

25 октября 2026 после приостановки новых регистраций Railway выбран Fly.io: один backend-сервис с фоновой обработкой и постоянным диском. Управляемая платформа позволяет сосредоточиться на сценарии приложения без администрирования VPS; небольшой перерыв при выкладке сервиса с диском допустим для dev-стенда. Локальный запуск сохраняется для разработки; отдельные staging и production на первом этапе не нужны.

Первоначальный выбор Railway заменён после сравнения [альтернатив](../research/hosting-alternatives.md). Форма приложения сохраняется: одна машина, один постоянный диск, ручная выкладка из GitHub Actions. Аккаунт Fly.io подключён; платные ресурсы ещё не созданы.

## Расходы

Ориентир расходов на инфраструктуру — до $10 в месяц, отдельно от AI API. Настраиваем уведомления и остановку dev-сервисов при достижении лимита потребления; порог определяем с учётом полного состава счёта. Пока backend остановлен, локальный гардероб доступен, новая обработка ждёт восстановления сервиса. Проектируемая конфигурация — shared CPU, 1 GB RAM, volume 3 GB, без масштабирования и snapshots. Оценка около $7–9 до трафика и налогов не является потолком счёта. Fly не предоставляет встроенных billing alerts; выполнение требования автоматической остановки по общему бюджету пока не подтверждено. До отдельного решения по бюджету и проверки платёжного источника платный запуск заблокирован. Выбор Fly и авторизация сами по себе не отменяют прежнее требование ограничения расходов.

## Временные данные

Постоянный диск сохраняет очередь и временные результаты между перезапусками и выкладками. Резервные копии этих серверных данных на первом этапе не создаём: оригиналы и уже доставленные результаты хранятся на клиенте. При потере диска незавершённую обработку потребуется повторить.

Для dev-стенда с публичными тестовыми фото согласовано исключение к сроку физического удаления: результаты становятся просроченными через 7 дней с загрузки, но при остановленном backend файлы могут оставаться на диске до следующего запуска. При запуске просроченные данные очищаются до возобновления обработки и не выдаются клиенту. В работающем сервисе сохраняется более ранняя очистка после подтверждённого сохранения результата на клиенте. Это исключение не переносится автоматически на личные фотографии; независимый от backend механизм удаления для строгого срока в первый этап не входит.
