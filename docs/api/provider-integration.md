# Протоколы провайдеров первого этапа

25 октября 2026 пользователь выбрал Photoroom + Jev (#22). Настоящие аккаунты и качество ещё не проверены; реальная проба остаётся в #10.

## Распознавание Jev

`POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <TYPESAFE_API_KEY>`, `TypeSafe-Danger-Zone-Images: true`, закреплённая модель `jev-1.14.0`. В одном запросе отправляются фото в `assets` и вопросы: пригодность фото и тип через Choice, наличие каждого из 14 цветов через Noul. Фото упоминается один раз в `state`, вопросы ссылаются на поле. Копия для Jev имеет стороны 280–1568 px: пропорции сохраняются, при необходимости добавляются поля. [Images](https://docs.typesafe.ai/images), [Choice](https://docs.typesafe.ai/primitives/choice), [Noul](https://docs.typesafe.ai/primitives/noul).

Источник вариантов — [shared/wardrobe-taxonomy.json](../../shared/wardrobe-taxonomy.json): 34 типа, включая «Не определён», и 14 цветов. Backend посылает стабильные ID с английскими описаниями, затем переводит выбранные ID в русские подписи существующего API. Тот же файл входит в iOS bundle для ручной правки. Справочник версионируется вместе с моделью в `providerConfig` и идентификаторе обработчика.

Проверяются версия ответа, Choice/Noul, допустимые ID и числовые значения. Начальный порог пригодности/типа — `confidence >= 0.7`, цвета — `noul >= 0.7`. Неуверенный тип становится «Не определён»; выбираются максимум пять уверенных цветов. Непригодное фото, неуверенная пригодность или отсутствие уверенного цвета не запускают платную вырезку. Это продуктовые начальные пороги для пробы, не измеренное качество распознавания одежды. [Confidence](https://docs.typesafe.ai/confidence).

Jev vision пока экспериментальный: поставщик не считает его готовым для production. Публичная ставка — $0.042 за миллион входных токенов, включая изображения; выход бесплатен. Точная формула предварительного расчёта image tokens и минимальная сумма пополнения не подтверждены. Не обещаем число фото из одного доллара до фактической пробы. [Images](https://docs.typesafe.ai/images), [Models](https://docs.typesafe.ai/models).

## Вырезка Photoroom

После успешного распознавания выполняется `POST https://sdk.photoroom.com/v1/segment` с `x-api-key` и multipart-полями `image_file`, `format=png`, `despill=false`. Photoroom получает нормализованный исходник, без изменения размера для Jev. API удаляет фон без генеративной перерисовки. PNG проверяется на размер, декодируемость, прозрачность и наличие видимых пикселей; метаданные удаляются. Это не доказывает качество сегментации: нужна визуальная проба. [Quickstart](https://docs.photoroom.com/remove-background-api-basic-plan/quickstart-guide), [despill](https://docs.photoroom.com/remove-background-api-basic-plan/green-screen-despill).

## Ошибки и допуск

SDK с автоматическими повторами, переключение модели и пополнение не используются. HTTP 401/403 — `provider_unauthorized`, 402/429 — `provider_quota_exceeded`, прочие 4xx — `provider_rejected`. 5xx, потерянный ответ и таймаут трактуются как `processing_unknown`: запрос мог расходовать квоту. Это относится и к остановке процесса между записью намерения и результата. Автоматического повтора нет. Сырые ошибки, ключи и фото не попадают в ответы API и логи.

Перед вызовами проверяются аккаунты, доступность, кредиты/квоты, согласованный бюджет и API opt-out Photoroom. `SAINT_LOOK_PROVIDER_PREFLIGHT_CONFIRMED` — ручное подтверждение, не автоматический контроль биллинга. Ключи только на backend. У Jev нет обучения на запросах без согласия, но стандартный сервис не обещает ZDR; для текущей пробы оставляем публичные фото. [Подключение аккаунтов](../research/provider-account-preflight.md), [TypeSafe legal](https://docs.typesafe.ai/legal).
