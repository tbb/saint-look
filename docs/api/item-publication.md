# Опубликованная версия вещи (#67)

Подготовка к единому допуску из [ADR-0004](../adr/0004-complete-item-readiness.md).
Эта задача вводит согласованный пакет и фиксацию фото существующей цепочки;
расчёт представлений и полный допуск #63 добавляет #68.

## Локальная публикация

`WardrobeItem.publishedVersion` хранит `versionID`, `photoVersionID`,
`sourceSetVersionID`, `cutoutFilename`, `cutoutMode`, `illustration`, `type`,
`colors`, `completeness`. Потребители изображения, категории и цветов читают
один пакет. Отсутствующее поле внутри пакета не берётся из другой версии.

`manualType/manualColors` — редактируемый ввод. Редактор показывает его;
после изменения готовой иллюстрации карточка и луки продолжают показывать
предыдущую версию. Существующее явное действие обновления запускает зависимые
этапы. Ошибка, отсутствие сети и перезапуск не удаляют опубликованный пакет.
После проверки identity и сохранения PNG/всех подготовленных исходников клиент
атомарно сохраняет `pendingPublication` — ещё невидимый пакет, запрос и ссылки
на файлы. До этого момента новые правки побеждают запоздалый ответ. Во время
короткого завершения публикации фото и признаки временно недоступны для изменения,
пока не выяснен исход подтверждения; прежняя опубликованная версия доступна.

Затем существующий `/ack` атомарно проверяет актуальность операции, фиксирует
набор фото и очищает временные артефакты сервера. Только получив 204, клиент
атомарно переключает `publishedVersion` и удаляет candidate. Ошибка сети или
перезапуск повторяет тот же ack из надёжно сохранённого candidate, без повторной
загрузки уже очищенных файлов и без новой генерации. Потерянный ответ commit
не отменяет commit: повтор по доставленной квитанции возвращает 204. Удаление
вещи побеждает и поздний ack. Окончательный отказ superseded/expired/deleted
не превращается в успешную публикацию.

Сервер линейризует гонку нового источника и commit: новый принятый запрос первым
делает старый ack неактуальным (409); commit первым делает новый набор
недопустимым (409 `photos_locked`). Нет окна, где клиент уже объявил вещь готовой,
а сервер ещё разрешает заменить фото. #68 добавляет обязательный encoder в
проверку готовности пакета **до** этой границы commit.

`legacyImage` означает прежнюю вырезку с признаками; `illustrated` — вырезку,
иллюстрацию и согласованные признаки текущего пайплайна. **Ни одно значение
не доказывает наличия или совместимости эмбеддингов.** #68 расширяет пакет
обязательным результатом encoder и проверкой полного допуска. До неё сохранён
существующий ручной конструктор. У legacy-вырезки без зависимой иллюстрации
изменение ручных признаков публикуется локально одним пакетом.

Миграция JSON сохраняет исходные файлы, ручные значения, идентичность вещей и
ссылки луков. Для старой согласованной иллюстрации опубликованные признаки
берутся из её `effectiveFeatures`; более новые ручные правки остаются черновиком.
Иллюстрация от другого фото не переносится в пакет новой фотографии.

## Фиксация фотографий

При подтверждении публикации через `/ack` сервер фиксирует весь набор: основное фото,
дополнительные фото, порядок, роли и версии. Изменение набора в следующем POST
иллюстрации возвращает 409 `photos_locked`; замена через `/attempts`, включая
подмену через `action: retry`, также запрещена. Повтор прежней операции остаётся
идемпотентным. Повтор обработки с прежним неизменным основным фото допустим.

Клиент сохраняет `photosLocked` вместе с публикацией. Скрыты замена фото и
редактирование ракурсов; те же ограничения проверяются в командах хранилища.
Просмотр фото остаётся доступен. Для другого фото нужна новая вещь с новым ID.
До первого commit исправление фото и явные повторы сохранены. Сам по себе
ответ генерации `ready`, даже после перезапуска сервера, фото не фиксирует.
Невостребованный результат устаревшего набора не мешает опубликовать новый.

`published_sources` — квитанция ID и хешей, а не серверный каталог: в ней нет
изображений, ручных признаков или результатов модели. Она живёт до DELETE вещи,
переживает ack, семидневную очистку временных данных и рестарт. DELETE удаляет
квитанцию, оставляя существующий tombstone ID. При миграции только подтверждённые доставленные иллюстрации фиксируют последний
согласованный набор текущего основного фото; завершение генерации не выдаётся
за факт публикации. Квитанция не содержит изображений, признаков или эмбеддингов.

## Версия данных и откат

Серверный формат 3 мигрирует форматы 1/2 без удаления данных. Код формата 2 не
умеет соблюдать новый запрет, поэтому откат к нему после миграции запрещён
проверкой SQLite `user_version`. Понижать marker вручную нельзя. Workflow выпуска
и health probe принимают формат 3 и проверяют точную выбранную версию.

## Проверки

HTTP с управляемой границей провайдеров проверяет правку ракурсов до первой
публикации при запоздалой генерации, отказ устаревшему ack, идемпотентность commit
после рестарта и неизменность после commit.
Операции каталога проверяют миграцию, публикацию целого пакета, отсутствие потери
при ошибке/сети/рестарте, отказ частичному и устаревшему ответу. Существующий
UI-сценарий переиспользования вырезок проверяет запрет новых ракурсов готовой вещи.
Эти проверки не заменяют ручную демонстрацию приложения и настоящую модель.
