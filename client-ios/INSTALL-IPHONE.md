# Установка Saint Look на iPhone с Mac

Платная подписка Apple Developer и локальная сборка проекта не нужны.
GitHub собирает Release для iOS 17+, Sideloadly подписывает его бесплатным
Apple Account на вашем Mac и устанавливает по USB.

## Один раз на Mac

1. Установите [Sideloadly с официального сайта](https://sideloadly.io/).
   Это сторонний инструмент, которому для подписи понадобится вход в Apple Account.
   Пароль вводится в Sideloadly на Mac; в GitHub и чат его передавать не нужно.
2. Установите [age](https://github.com/FiloSottile/age#installation).
   Если уже есть Homebrew: `brew install age`.
3. Сохраните отдельно переданный файл `saint-look-identity.txt` в надёжное место.
   Например, `~/.config/saint-look/saint-look-identity.txt` с правами `600`.
   Этот ключ открывает персональные сборки; его нет в GitHub и публичных артефактах.
4. Подключите разблокированный iPhone кабелем и подтвердите доверие Mac.

## Получить и установить сборку

1. В [Actions → iPhone IPA](https://github.com/tbb/saint-look/actions/workflows/ios-ipa.yml)
   нажмите **Run workflow**, выберите **main**. Дождитесь зелёного результата.
2. Скачайте артефакт `SaintLook-iPhone-<SHA>` и распакуйте внешний ZIP.
   Внутри находится `SaintLook.ipa.age`.
3. Расшифруйте пакет, указав реальные пути к ключу и скачанному файлу:

   ```bash
   umask 077
   age --decrypt \
     --identity ~/.config/saint-look/saint-look-identity.txt \
     --output ~/Downloads/SaintLook.ipa \
     ~/Downloads/SaintLook.ipa.age
   ```

   Если `SaintLook.ipa` уже существует от прошлой сборки, сначала перенесите
   или удалите именно этот старый файл.
4. Откройте Sideloadly, выберите iPhone, перетащите `SaintLook.ipa`, укажите
   Apple Account и нажмите **Start**. Подтвердите вход, если потребуется.
   **Обновляйте поверх установленного приложения, не удаляя его.** Вещи, фото
   и луки хранятся на iPhone; удаление приложения стирает их. Backend не является
   резервной копией: полученные приложением результаты очищаются на сервере.
   Для следующих обновлений используйте тот же аккаунт и bundle ID:
   смена идентичности может создать отдельное приложение с другим локальным гардеробом.
5. При запросе iOS доверьтесь профилю своего аккаунта в
   **Настройки → Основные → VPN и управление устройством**.
   Включите **Настройки → Конфиденциальность и безопасность → Режим разработчика**,
   перезагрузите iPhone и подтвердите включение. Если пункт пока не появился,
   завершите подключение и попытку установки с Mac.
6. Откройте Saint Look. В персональной сборке адрес Fly и токен уже заданы:
   при первом запуске токен сохраняется в Keychain. Сохранённые вручную настройки
   не перезаписываются при обновлении. Если токен владельца сменился, обновите его
   в настройках приложения — новая IPA не перезапишет ранее сохранённый токен.
   После переустановки адрес восстановится из персональной IPA, если сохранившийся
   в Keychain токен совпадает с её токеном. Токен без известного адреса потребует
   настройки подключения; фотографии и луки это не восстанавливает.

У бесплатного Apple Account подпись действует **7 дней**, одновременно разрешено
до **3 тестовых приложений**. После истечения обновите подпись через Sideloadly;
он также поддерживает автоматическое обновление при доступном Mac/iPhone.
Не удаляйте приложение для обычного обновления: удаление стирает локальный гардероб.
Сама повторная подпись не требует пересборки в GitHub.

## Что проверяет эта сборка

Workflow компилирует настоящий arm64 iPhoneOS Release. На PR он проверяет упаковку,
расшифровку и отказ с чужим ключом на одноразовых тестовых данных, без реальных
секретов и без публикации персональной IPA. Личный артефакт создаётся только
ручным запуском из `main`, хранится 7 дней и требует ключ для расшифровки.

IPA не подписана Apple до установки через Sideloadly. Успешная компиляция и
проверка упаковки не заменяют установку на реальный iPhone: её выполняет владелец.
Ручной PhotosPicker/офлайн-перезапуск отслеживаются в
[#13](https://github.com/tbb/saint-look/issues/13), настоящая обработка на Fly — в
[#10](https://github.com/tbb/saint-look/issues/10).
Сборка IPA **не выкладывает backend и не переключает его в live-режим**.
В режиме demo приложение явно показывает демонстрационные результаты.

## Настройки GitHub и безопасность артефакта

- Variable `SAINT_LOOK_DEV_URL`: HTTPS-адрес backend.
- Secret `SAINT_LOOK_DEV_OWNER_TOKEN`: доступ владельца; ключей Photoroom/Jev в приложении нет.
- Variable `IOS_IPA_AGE_RECIPIENT`: открытый age-ключ получателя (`age1…`).
  Закрытый ключ `saint-look-identity.txt` хранится только у получателя/в приватной
  передаче при настройке, в Actions не загружается.

Для нового получателя можно создать пару локально:

```bash
umask 077
age-keygen -o saint-look-identity.txt
age-keygen -y saint-look-identity.txt
```

В GitHub Variable копируется только вывод второй команды. При утрате ключа
создайте новую пару, замените Variable и запустите сборку снова. Старые артефакты
новым ключом не открыть. При компрометации ключа также смените токен владельца:
смена получателя не отзывает доступ к старым скачанным IPA.

Токен добавляется после компиляции только во временную копию приложения.
Пакет публикуется после шифрования age; архивы Xcode, промежуточная IPA и закрытые
ключи не загружаются. Расшифрованную IPA не распространяйте: токен можно извлечь
из неё, и он даёт доступ владельца к dev-backend. Это личная тестовая сборка,
не способ распространять приложение другим пользователям.

Источники: [ограничения бесплатного аккаунта Apple](https://developer.apple.com/help/account/basics/about-your-developer-account),
[Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device),
[Sideloadly](https://sideloadly.io/), [age](https://github.com/FiloSottile/age).
