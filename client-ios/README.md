# iOS: локальный срез #2

SwiftUI-приложение для iOS 17+. Откройте `SaintLook.xcodeproj` в Xcode и выберите общую схему `SaintLook` и iPhone Simulator. Внешних Swift-пакетов нет. Для запуска на устройстве потребуется выбрать свой signing team; HTTP разрешён только для loopback, для удалённого backend нужен HTTPS.

Запустите локальный backend из `../backend` и укажите в настройках приложения его адрес и токен владельца. Simulator использует `http://127.0.0.1:8787` на Mac. Токен сохраняется в Keychain, фотографии и каталог — в Application Support. Ключи AI-провайдеров приложению не нужны.

«Добавить фото» открывает системный PhotosPicker без запроса доступа ко всей медиатеке. Исходник и pending-карточка сохраняются перед отправкой. Для backend приложение создаёт PNG без метаданных, с длинной стороной до 2048 px; исходник остаётся на устройстве. Лимиты: исходник до 20 MiB, отправляемая копия до 5 MiB. После получения результата вырезка, тип и цвета сохраняются локально и доступны после перезапуска без backend. Ошибка соединения сохраняет карточку и фото; полноценные повторы отправки входят в отдельную задачу #4.

Весь этот срез работает в явно обозначенном тестовом режиме: backend возвращает синтетическую вырезку, тип и цвет. В Debug также есть кнопка «Добавить тестовое фото»: она создаёт изображение и вызывает тот же путь сохранения и отправки, что PhotosPicker. В Release кнопки и переменных окружения для UI-тестов нет.

## Simulator UI E2E

На Mac запустите настоящий backend с пустым временным хранилищем, fixture-адаптером, задержкой ответа не менее 1500 ms и **только тестовым** токеном `saint-look-ui-tests-owner-token-00000001` на порту 8787. Затем:

```bash
./client-ios/scripts/test-simulator.sh
```

Скрипт выбирает доступный iPhone Simulator или использует `SAINT_LOOK_SIMULATOR_UDID`, отключает параллельные клоны и сохраняет `.xcresult` в `client-ios/build/`. Альтернативные адрес/токен тестового backend задаются `SAINT_LOOK_UI_TEST_URL` / `SAINT_LOOK_UI_TEST_TOKEN` в окружении test runner. Обычные настройки приложения эти переменные не читают.

Тесты через UI добавляют фото, наблюдают pending → ready, проверяют тип/цвет и сохранение результата после перезапуска с недоступным backend. Второй сценарий проверяет сохранение фото и pending-карточки при ошибке сети. Внешний AI не вызывается. Детерминированная кнопка обходит только системный выбор фото; сам PhotosPicker этими тестами не проверяется.

В среде реализации Linux нет Xcode: сборка и UI-тесты здесь **не запускались**. Перед признанием среза проверенным требуется зелёный Simulator-прогон и ручной выбор настоящей фотографии через PhotosPicker.
