# iOS: локальный срез #2

SwiftUI-приложение для iOS 17+. Откройте `SaintLook.xcodeproj` в Xcode и выберите общую схему `SaintLook` и iPhone Simulator. Внешних Swift-пакетов нет. Для запуска на устройстве потребуется выбрать свой signing team; HTTP разрешён только для loopback, для удалённого backend нужен HTTPS.

Запустите локальный backend из `../backend` и укажите в настройках приложения его адрес и токен владельца. Simulator использует `http://127.0.0.1:8787` на Mac. Токен сохраняется в Keychain, фотографии и каталог — в Application Support. Ключи AI-провайдеров приложению не нужны.

«Добавить фото» открывает системный PhotosPicker без запроса доступа ко всей медиатеке. Исходник и pending-карточка сохраняются перед отправкой. Для backend приложение создаёт PNG без метаданных, с длинной стороной до 2048 px; исходник остаётся на устройстве. Лимиты: исходник до 20 MiB, отправляемая копия до 5 MiB. После получения результата вырезка, тип и цвета сохраняются локально и доступны после перезапуска без backend. При ошибке соединения карточка остаётся ожидающей. Пока приложение открыто, оно автоматически повторяет согласование с backend с паузой до 10 секунд; в фоне постоянная работа не требуется. Повтор использует прежние идентификаторы вещи, операции и снимка. Подробнее: [офлайн-восстановление](../docs/offline-ingestion.md).

Клиент различает режимы backend: `demo` явно обозначен в интерфейсе и на готовой карточке, `live` получает обычную отметку готовности. Режим результата сохраняется вместе с карточкой. Управляемые внешние ответы в тестах обозначены как demo; это не доказательство подключения настоящих аккаунтов. В Debug также есть кнопка «Добавить тестовое фото»: она создаёт изображение и вызывает тот же путь сохранения и отправки, что PhotosPicker. В Release кнопки и переменных окружения для UI-тестов нет.

## Simulator UI E2E

На Mac запустите настоящий backend с пустым временным хранилищем, `SAINT_LOOK_PROVIDER=demo`, задержкой ответа не менее 1500 ms и **только тестовым** токеном `saint-look-ui-tests-owner-token-00000001` на порту 8787. В отдельном терминале запустите тестовый HTTP-прокси, затем тесты:

```bash
NODE_ENV=test node client-ios/scripts/ui-test-proxy.mjs
```

```bash
./client-ios/scripts/test-simulator.sh
```

Прокси слушает только `127.0.0.1:8788` и принимает только loopback upstream с режимом demo. Тесты управляют разрывами соединения через защищённый тестовым токеном `/__control`; рабочий backend таких маршрутов не имеет. Фото и токены в диагностический вывод не пишутся. Прокси умеет отключить передачу до приёма и оборвать ответ уже после приёма загрузки настоящим backend.

Скрипт выбирает доступный iPhone Simulator или использует `SAINT_LOOK_SIMULATOR_UDID`, отключает параллельные клоны и сохраняет `.xcresult` в `client-ios/build/`. Приложение теста подключается к прокси `http://127.0.0.1:8788`; альтернативные адрес/токен задаются `SAINT_LOOK_UI_TEST_URL` / `SAINT_LOOK_UI_TEST_TOKEN`. Управление использует `SAINT_LOOK_UI_TEST_CONTROL_URL` (по умолчанию `http://127.0.0.1:8788/__control`) и `SAINT_LOOK_UI_TEST_CONTROL_TOKEN` (по умолчанию `saint-look-ui-control-test-token-00000001`). Переменные должны быть доступны test runner. Для другого порта backend задайте прокси `SAINT_LOOK_UI_PROXY_UPSTREAM`, для порта прокси — `SAINT_LOOK_UI_PROXY_PORT`. Обычные настройки приложения эти переменные не читают.

Тесты через UI добавляют фото, наблюдают pending → ready, проверяют тип/цвет и сохранение результата после перезапуска с недоступным backend. Остальные сценарии проверяют сохранение фото при ошибке сети, несколько офлайн-добавлений с перезапуском и автоматическим продолжением без ручного действия, а также потерю ответа уже принятой загрузки без второй вещи. Скрипт сначала выполняет `build-for-testing`, затем добавляет HTTP-исключения только для loopback в plist сгенерированного UI test host и запускает `test-without-building`: настройки ATS приложения не распространяются на отдельный test host. Внешний AI не вызывается. Детерминированная кнопка обходит только системный выбор фото; сам PhotosPicker этими тестами не проверяется.

В среде реализации Linux нет Xcode: новые сценарии #4 здесь **не запускались**. Результат hosted Simulator-прогона фиксируется в PR. Перед признанием среза проверенным требуется зелёный Simulator-прогон и ручной выбор настоящей фотографии через PhotosPicker.
