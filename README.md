# Saint Look

Цифровой гардероб и сохранённые луки из настоящих вещей.

## Гардероб и временное хранение: #2–#8

В `backend/` и `client-ios/` реализован путь фото → ожидание → карточка → локальное чтение без сети. Несколько офлайн-добавлений сохраняются между запусками; отправка автоматически продолжается в открытом приложении после восстановления связи. Backend хранит этапы обработки и не повторяет внешний запрос с неизвестным исходом.

Режим `demo` возвращает явно обозначенный синтетический результат. Для `live` добавлены адаптеры Gemini и Photoroom; реальные аккаунты и качество ещё не проверены. Перед настоящими вызовами требуются ключи и подтверждение проверки бесплатных квот, доступности аккаунтов и opt-out Photoroom. Автоматического перехода на платный тариф или подмены ошибочного live-результата demo нет.

Запуск: [backend](backend/README.md), [iOS](client-ios/README.md), [общий API](docs/api/local-ingestion.md). Подробности: [провайдеры](docs/api/provider-integration.md), [офлайн-восстановление](docs/offline-ingestion.md). Тип и цвета можно исправить в карточке без сети; ручные значения сохраняются после перезапуска и имеют приоритет над результатом обработки. Явный повтор обработки и замена фото сохраняют вещь, ручные правки и предыдущую хорошую вырезку до готовности новой. Поздние результаты старых попыток не заменяют текущую версию. Удаление работает без сети: карточка исчезает после локального сохранения, команда переживает перезапуск и доставляется автоматически. Поздние ответы не восстанавливают вещь; очищаются её локальные версии и серверные изображения/результаты. Ручная выкладка dev-стенда готовится в #9; проба реальных API относится к #10. Ручная проверка PhotosPicker отложена пользователем.

Проверки на PR и после merge в `main` описаны в `.github/workflows/ci.yml`: Linux HTTP-тесты и macOS Simulator с настоящим локальным backend. Репозиторий публичный; используемые стандартные `ubuntu-latest` и `macos-26` бесплатны. Если репозиторий станет приватным, все задания заблокируются до установки `ACTIONS_BUDGET_VERIFIED=true` после проверки включённой квоты и бюджета платного превышения $0 с остановкой. Переменная — ручной допуск, не автоматическая проверка биллинга. В CI нет реальных AI-вызовов. Статус выполнения проверок см. в PR; системный выбор фото дополнительно проверяется на Mac.

Подтверждение надёжно сохранённого результата очищает серверную копию; локальная карточка остаётся доступной офлайн. Незабранные временные данные истекают через 7 дней, после чего клиент предлагает явный повтор из исходника. Подробности — в [инструкции iOS](client-ios/README.md#подтверждение-доставки-и-срок-хранения).

## Dev-стенд и ручная выкладка: #9

Подготовка Fly.io и ручного deploy описана в [инструкции](docs/deployment.md), проверенные ограничения платформы — в [исследовании](docs/research/hosting-alternatives.md). Workflow принимает конкретный коммит из `main` с успешным полным CI. Контейнер dev-стенда использует управляемые HTTP-ответы провайдеров и явно возвращает `mode: demo`; реальные AI API не вызываются.

Аккаунт, оплата, приложение Fly.io, volume и секреты Actions подготовлены. Для dev согласована фиксированная конфигурация около $7–9/месяц плюс трафик и налоги без автоостановки на $10. Машина ещё не развёрнута: первый deploy требует merge и успешного main push CI. Удалённый Simulator, сохранность очереди/результатов и возврат предыдущей версии пока не подтверждены.
